# Face Gate — распознавание лиц на проходной кампуса

Системный дизайн CV/ML-системы прохода по лицу: от кадра с камеры до команды турникету,
с обязательным уходом сомнительных случаев на ручной контроль охраны.

> Статус: отборочное задание, тайм-бокс 4 часа. Это **не** production-система.
> Документация — основной артефакт, PoC — подтверждение одного сценария.

## Зачем это бизнесу

Кампус на 12 000 сотрудников делает около 19 000 проходов в день, и почти половина
приходится на два пика. В пике очередь добавляет в среднем 90 секунд на человека —
это единственная статья, где скрыты основные деньги: около **15.8 млн ₽ в год**
рабочего времени, стоящего в очереди, против примерно 1.2 млн ₽ на ручных разборах
у охраны. Проход по лицу убирает операцию «достать карту»
и позволяет вести несколько человек параллельно, а безбумажный разбор забытых
пропусков снимает с охраны около 40 ручных случаев в день. Отдельно система закрывает
дыру, которую карта закрыть не может в принципе: карту можно передать коллеге,
и текущая система об этом не узнает. Расчёт с допущениями — в
[docs/product.md](docs/product.md#4-расчёт-годового-эффекта-mvp).

## Ключевые решения одним взглядом

1. **Инференс на edge, идентификация в центре.** Детекция, качество, liveness и
   извлечение эмбеддинга выполняются на edge-узле проходной; поиск one-to-many идёт
   по ANN-индексу — в центре, с горячим локальным кешем на edge для деградации.
2. **Три исхода, а не два.** `allow` / `manual_review` / `deny`. Любая неуверенность
   уходит охране и **никогда** не открывает турникет автоматически.
3. **Ассиметрия ошибок зашита в пороги.** False accept — инцидент безопасности
   стоимостью на три порядка выше, чем false reject. Пороги подобраны по рабочей точке
   FAR, а не по максимуму accuracy.
4. **Хранятся эмбеддинги, а не лица.** Исходные кадры удаляются после обработки;
   исключение — короткое окно хранения кадров для спорных решений (см. risks-and-ops).
5. **Деградация не открывает дверь.** Offline-режим и устаревший кеш понижают систему
   до `manual_review`, потому что отзыв доступа мог не доехать.

## Быстрый старт

Зависимостей нет — только стандартная библиотека Python 3.10+.

```bash
python scripts/run_demo.py          # прогон всех семи сценариев + проверка идемпотентности
```

```bash
python -m unittest discover tests   # 13 smoke-тестов
```

```bash
python -m poc.api                   # HTTP-сервис на localhost:8080
```

Проверка API:

```bash
curl -X POST http://localhost:8080/v1/access/verify -H "Content-Type: application/json" -d @demo/events/e-1001.json
```

В контейнере (образ без зависимостей, только базовый Python):

```bash
docker build -t face-gate-poc . && docker run --rm face-gate-poc
```

Демонстрируемый сценарий: событие с камеры проходит детекцию, оценку качества,
liveness и матчинг, после чего политика возвращает одно из трёх решений и пишет
запись в audit log.

| Событие | Что демонстрирует | Решение |
|---|---|---|
| `e-1001` | **happy path** — хорошие условия | `allow`, турникет открывается |
| `e-1002` | маска и контровый свет | `manual_review` |
| `e-1003` | **risky path** — фото с экрана телефона | `deny` + эскалация как атака |
| `e-1004` | два близких кандидата, отрыв 0.005 | `manual_review` |
| `e-1005` | offline, доступ отозван вчера | `deny` + эскалация |
| `e-1006` | **fallback path** — offline, кеш старше 60 мин | `manual_review`, автооткрытия нет |
| `e-1007` | два лица в кадре | `manual_review`, подозрение на tailgating |

Из семи сценариев турникет открывается ровно в одном. Повтор `e-1001` возвращает то же
решение с командой `noop` — двойное открытие невозможно.

> Если повторный `curl` с тем же `event_id` вернул `noop`, это не ошибка, а работающая
> идемпотентность: событие уже есть в audit log. Чтобы увидеть `open` снова, поменяйте
> `event_id` в теле запроса или удалите каталог `var/`.

| Извлечение эмбеддинга | **mock** — детерминированный вектор от `person_id` + шум условий |

## Допущения и ограничения

Все продуктовые допущения помечены как `A1…A7` в
[docs/product.md](docs/product.md#допущения). Главное из них: цена одного false accept
принята равной **500 000 ₽** — обоснование порядка величины там же.

Технические ограничения PoC: нет реальных изображений и реальных моделей, поэтому
цифры FAR/FRR в [docs/ml.md](docs/ml.md) — это **целевые рабочие точки из публичных
бенчмарков**, а не измерения на этих данных. Ни одна метрика качества в репозитории
не получена экспериментально, и это указано в каждом месте, где такие числа приводятся.

## Риски, не закрытые в MVP

Presentation attacks уровня 3D-масок; tailgating — проход «паровозиком» за
распознанным сотрудником; смещение качества модели по демографическим подгруппам,
которое нельзя измерить без размеченного набора; юридическая сторона обработки
биометрии. Подробнее — [SELF_REVIEW.md](SELF_REVIEW.md).
